# CRM Import Converter

> **Язык:** Русский (этот файл) · [English](README.md)
>
> Точно такой же сервис с **английским интерфейсом** — в отдельном репозитории:
> [crm-import-converter](https://github.com/alexeyd-sudo/crm-import-converter).
> Код тот же, отличаются только строки интерфейса, сообщения и подписи в отчётах.

Веб-сервис: произвольная таблица лидов (Excel/CSV) → CSV, готовый для импорта
в CRM (диалект совместим с проверенным `reference_import.csv`).

```
cd NEW
py -m venv venv && venv\Scripts\activate
pip install -r requirements.txt
py app.py            →  http://localhost:5000
```

Порт берётся из переменной окружения `PORT`, по умолчанию здесь **5000**
(у английской версии — **5001**), поэтому обе версии можно держать
запущенными одновременно:

```
set PORT=5050 && py app.py
```

## Как это работает

1. **Загрузка файла** — `.xlsx`, `.xlsm` или `.csv`, до 25 МБ.
   Первая строка — заголовки колонок.

2. **Проверка данных.** Сервис классифицирует содержимое каждой колонки
   (e-mail / телефон / сайт / текст), находит телефонные колонки и достаёт до
   5 номеров из каждой ячейки, приводя их к формату `+…`. Ячейка с несколькими
   номерами превращается в под-столбцы `— Phone 1`, `— Phone 2`, …, которые
   можно разложить по разным полям CRM.

3. **Сопоставление полей.** Поля справа предзаполнены автоматически (по
   заголовку и по содержимому) — их нужно проверить. Целевые поля:

   * **Company Name / Lead Name** — одно значение сразу в 2 колонки результата
   * **Mobile / Home / Other Phone**
   * **Corporate / Other Website**
   * **Work / Home / Other E-mail**
   * **Country OUTREACH / Outreach comment / Comment** — необязательные
   * **Source** — не показывается, во все строки ставится `import`

4. **Результат** — два файла и два отчёта.

## Две ключевые особенности

### Дубли: два файла вместо одного

Сервис никогда не решает за вас. Он отдаёт **и** полный файл (строка-в-строку
как в источнике), **и** чистый (дубли объединены, данные из всех копий собраны
в одну строку), **и** CSV-отчёт «какие строки в какую склеились и по какому
признаку» — с номерами строк исходного Excel.

Признаки объединения включаются галочками: название компании (с учётом хендла
в скобках — `Alpha (alpha_mx)` = `alpha_mx`), e-mail, телефон
(последние 9 цифр — номер с кодом страны и без считается одним), сайт.

На реальной базе: **436 строк → 355**, 57 групп дублей, строк совсем без
контактов стало 35 → 14 (объединение восстанавливает данные из «обеднённых» копий).

### Перепутанные поля исправляются автоматически

Тип значения определяется **по содержимому, а не по заголовку колонки**:

| Признак | Тип |
|---|---|
| есть `@` | e-mail |
| только цифры, `+`, скобки, дефисы | телефон |
| схема `http(s)://`, префикс `www.` или домен с реальной зоной | сайт |

E-mail, вписанный в колонку телефона, уедет в поле E-mail; ссылка — в Website;
номер из колонки сайта — в Phone. Если такое значение там уже есть, оно
отбрасывается как дубликат. Всё это попадает в отчёт `field_fixes_report.csv`
с номером строки — автоматику можно проверить.

## Формат результата

`;` как разделитель, CRLF, кавычки только там, где нужны. Разделитель `;` —
как в `reference_import.csv`, файле, который импортировался корректно. Legacy-скрипт
`../convert_to_csv.py` писал `,` + кавычки вокруг каждого поля, из-за чего вся
строка попадала в одну колонку.

Кодировка **выбирается на шаге 3**, по умолчанию **UTF-8 с BOM**. BOM — метка
в начале файла, по которой Excel и большинство импортёров определяют кодировку
автоматически. Без неё получатель читает 2 байта буквы `é` как 2 символа своей
ANSI-кодировки, и после приведения к ASCII получается `México → M??xico`
(два `?` на одну букву — характерная подпись двойной перекодировки).

Если CRM ломает буквы при любой кодировке — есть галочка **«Транслитерировать
диакритику»** (`México → Mexico`): результат становится чистым ASCII, испортить
его перекодировкой уже невозможно. Подробности — в
[docs/SUPPORT.md](docs/SUPPORT.md).

## Прод

```

```

**Ровно 1 worker** — состояние сессии хранится в памяти процесса.
Подробности и переменные окружения — в [docs/DEVELOPER.md](docs/DEVELOPER.md).

## Ограничения

* Максимальный размер файла — 25 МБ (`MAX_CONTENT_LENGTH` в `app.py`),
  200 000 строк и 300 колонок (`MAX_ROWS`/`MAX_COLS` в `converter.py`).
* Сессии живут 6 часов, потом удаляются вместе с загруженным файлом
  (`SESSION_TTL_SECONDS`).
* Из одной ячейки достаётся максимум 5 телефонов (`MAX_PHONES_PER_CELL`);
  превышение не отбрасывается молча, а показывается предупреждением.
* **Аутентификации нет** — сервис для внутреннего контура, наружу выставлять
  только за reverse-proxy с авторизацией.

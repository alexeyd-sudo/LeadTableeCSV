# Руководство поддержки

Для тех, кто пользуется сервисом и отвечает на вопросы пользователей.
Технические детали — в [DEVELOPER.md](DEVELOPER.md).

---

## 1. Что делает сервис

Превращает произвольную таблицу лидов (Excel или CSV) в CSV для импорта в CRM.
По дороге:

* определяет, что реально лежит в каждой колонке (e-mail / телефон / сайт / текст);
* достаёт несколько телефонов из одной ячейки и приводит их к формату `+…`;
* **переносит значения, попавшие не в свою колонку** (e-mail в графе телефона и т.п.);
* **находит дубликаты компаний** и отдаёт два файла — с дублями и без;
* пишет два CSV-отчёта, по которым можно проверить обе автоматики.

---

## 2. Порядок работы

### Шаг 1. Файл

Перетащите `.xlsx`, `.xlsm` или `.csv` (до 25 МБ). **Первая строка файла должна
быть строкой заголовков.**

### Шаг 2. Проверка данных

Идёт автоматически. Сервис читает файл, классифицирует колонки и разбирает
телефоны.

### Шаг 3. Сопоставление полей

Слева — колонки исходника, справа — поля CRM.

* Поля справа **уже заполнены автоматически** (подсвечены синей рамкой) — по
  названию колонки и по её содержимому. **Это предположение, проверьте его.**
* У каждой колонки стоит цветной ярлык типа (`e-mail` / `телефон` / `сайт` /
  `текст`). Наведите на него мышь — покажет, сколько ячеек какого типа нашлось.
* Если в одной ячейке было несколько телефонов, колонка разбита на
  `— Phone 1`, `— Phone 2`, … Их можно разложить по разным полям CRM.
* Сверху — жёлтые предупреждения. Прочитайте их: там пишется, если найдены
  ссылки в телефонной колонке, номера без кода страны и т.п.
* **Поле `Source`** не показывается — во все строки автоматически ставится `import`.
* Несколько колонок можно направить в одно поле — значения склеятся через `, `.

**Настройки обработки** (раскрывающийся блок внизу):

| Настройка | По умолчанию | Когда менять |
|---|---|---|
| Исправлять перепутанные поля | **вкл** | Выключить, только если нужно «как есть», без переносов |
| Пропускать строки без названия компании | выкл | Включить, если в файле есть «хвост» из пустых строк |
| Защита от формул Excel | выкл | Включить, только если файл будут открывать в Excel. **Для импорта в CRM не включать** — она добавит `'` перед телефонами |
| Код страны по умолчанию | пусто | Указать, если в файле номера без `+` и без кода страны, а страна известна (`52` Мексика, `57` Колумбия, `56` Чили, `54` Аргентина, `598` Уругвай, `507` Панама) |
| Кодировка CSV | **UTF-8 с BOM** | Менять, только если CRM показывает `M??xico` / `MÃ©xico` — см. раздел «Частые вопросы» |
| Транслитерировать диакритику | выкл | Включить, если CRM ломает буквы при любой кодировке: `México → Mexico`. Даёт чистый ASCII, который невозможно испортить |
| Объединять по названию | **вкл** | — |
| Объединять по e-mail | **вкл** | — |
| Объединять по телефону | **вкл** | Выключить, если у компаний может быть общий номер (колл-центр, агентство) |
| Объединять по сайту | выкл | Включить, если у каждой компании свой домен |

### Шаг 4. Результат

Два файла:

| Файл | Что внутри | Когда брать |
|---|---|---|
| **Чистый CSV** (`crm_import_merged.csv`) | дубликаты объединены, данные из всех копий собраны в одну строку | обычный случай — **берите этот** |
| **CSV с дублями** (`crm_import_with_duplicates.csv`) | строка-в-строку как в источнике | когда нужна ручная сверка, или когда объединение вам не подходит |

Два отчёта (тоже CSV, открываются в Excel):

| Отчёт | Колонки | Зачем |
|---|---|---|
| `duplicates_report.csv` | группа, оставленное название, сколько строк, **номер строки исходника**, исходное название, по чему совпало | проверить, что склеены действительно одинаковые компании |
| `field_fixes_report.csv` | **номер строки исходника**, колонка, определённый тип, значение, куда было сопоставлено, куда перенесено | проверить, что значения перенесены правильно |

Номера строк в отчётах **совпадают с номерами строк в Excel** (строка 1 — заголовки).

На экране те же данные показываются в раскрывающихся блоках (первые 50 записей),
плюс превью первых 5 строк каждого файла.

## 3. Формат результата

* Разделитель — **точка с запятой `;`**
* Кодировка — выбирается на шаге 3, по умолчанию **UTF-8 с BOM**
* Переносы строк — `CRLF`
* Кавычки — только там, где нужны
* Колонки — фиксированные 14:
  `Company Name; Lead Name; Mobile Phone; Home Phone; Other Phone Number;
  Corporate Website; Other Website; Work E-mail; Home E-mail; Other E-mail;
  Country OUTREACH; Outreach comment; Comment; Source`

## 4. Частые вопросы и проблемы

### «В CRM вся строка попала в одну колонку»

CRM ждёт другой разделитель. Файл пишется с `;` — так устроен эталонный
`reference_import.csv`. Если конкретная система ждёт запятую, поменяйте
`CSV_DELIMITER` в `converter.py` (см. DEVELOPER.md).

### «Вместо México — `M??xico`, вместо Estética — `Est??tica`»

**Два** знака вопроса на одну букву — это подпись двойной перекодировки.
Наш файл в UTF-8, буква `é` в нём занимает 2 байта (`C3 A9`). Получатель не
понял, что файл в UTF-8, прочитал эти 2 байта как 2 отдельных символа
системной кодировки, а потом урезал результат до ASCII — каждый символ стал `?`.

Порядок действий, от простого к надёжному:

1. **Кодировка = «UTF-8 с BOM»** (значение по умолчанию). BOM — это метка в
   начале файла, по которой Excel и большинство импортёров понимают кодировку
   автоматически. Если у вас стоит «UTF-8 без BOM» — переключите обратно.
2. **Кодировка = «Windows-1252 (латиница)».** Однобайтовая кодировка, `é í ñ ó`
   в ней есть. Помогает, если импортёр вообще не умеет UTF-8. Кириллица при
   этом не сохранится — сервис предупредит, сколько символов потеряно.
3. **Галочка «Транслитерировать диакритику».** `México → Mexico`,
   `Estética → Estetica`. Файл становится чистым ASCII — испортить его
   перекодировкой уже невозможно в принципе. Это самый надёжный вариант,
   и именно так (только с потерей букв на `?`) был устроен старый эталонный
   `reference_import.csv`, который импортировался корректно.

Один `?` вместо буквы (`M?xico`) — тот же диагноз, но получатель урезал до
ASCII сразу, без промежуточной перекодировки. Лечится так же.

### «Вместо é — `Ã©` или `Г©`»

Половина той же болезни: получатель прочитал UTF-8 как однобайтовую кодировку,
но до ASCII не резал. Решение то же — см. предыдущий пункт.

### «Открываю результат в Excel — кракозябры»

Если стоит «UTF-8 без BOM», Excel по двойному клику кодировку не угадывает.
Либо переключите на «UTF-8 с BOM», либо открывайте через
*Данные → Из текста/CSV* → кодировка UTF-8.

**Отчёты** (`duplicates_report.csv`, `field_fixes_report.csv`) всегда пишутся
в UTF-8 с BOM независимо от настройки — они предназначены для чтения в Excel.

### «Excel показывает `#ИМЯ?` вместо телефона»

Excel считает `+52 55 …` формулой. Это проблема **только просмотра в Excel** —
в CRM импортируется корректно. Если файл нужен именно для Excel, включите
«Защита от формул Excel» на шаге 3.

### «Сервис объединил две разные компании»

Скорее всего сработало объединение по телефону. Посмотрите
`duplicates_report.csv` — в колонке *Matched on* написано, по чему совпало.
Снимите галочку «по телефону» и сформируйте файл заново (файл перезагружать
не нужно, если сессия жива).

### «Сервис не объединил очевидные дубли»

Названия различаются, а телефона/e-mail нет ни у одной из строк — сцепить не по
чему. Вариант: включить объединение по сайту. Либо взять файл с дублями и
объединить вручную.

### «Колонка не разбилась на телефоны» / «разбилась зря»

Колонка считается телефонной, если её заголовок содержит слово `phone`, `tel`,
`whatsapp`, `cel`, `móvil`, `телефон`… **или** если ≥50 % заполненных ячеек
выглядят как номер. Заголовки со словами `mail`, `website`, `url`, `id`, `zip`,
`date`, `price` телефонными не считаются никогда.

Если определилось неправильно — ничего не потеряно: в выпадающем списке можно
направить колонку в любое поле, а перепутанные значения всё равно будут найдены.

### «Сессия не найдена или истекла»

Сессия живёт 6 часов (или до перезапуска сервиса). Загрузите файл заново.

### «Файл больше 25 МБ»

Лимит в `app.py`, `MAX_CONTENT_LENGTH`. Либо разбейте файл на части.

### «В файле не найдено данных»

Первая строка должна быть заголовками, а не названием отчёта или пустой строкой.
Удалите шапку над таблицей и загрузите снова.

## 5. Проверка, что сервис жив

```
curl http://localhost:5000/healthz
{"status":"ok","sessions":3}
```

Прогон автотестов (займёт несколько секунд, ничего не портит):

```
cd NEW
py tests\test_converter.py
```

Ожидается `40/40 passed`. Если что-то падает — приложите вывод к тикету.

## 6. Что приложить к обращению в разработку

1. Исходный файл (или его фрагмент со строкой-проблемой).
2. **Номер строки** в исходнике.
3. Что получилось и что ожидалось.
4. Оба отчёта (`duplicates_report.csv`, `field_fixes_report.csv`).
5. Скриншот шага 3 (сопоставление + настройки).
6. Кусок `server.log` за время обращения.

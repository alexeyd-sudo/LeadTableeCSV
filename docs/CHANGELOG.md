# История изменений

## v2.1 — кодировка результата

Симптом: после импорта названия вида `Alpha Estética México (alphaestética)`
превращались в `Medi M??xico Distribuidora (medim??xico)`.

**Причина не в сервисе** — на выходе был корректный UTF-8 (`M\xc3\xa9xico`).
Файл писался **без BOM**, получатель не распознал кодировку, прочитал 2 байта
буквы `é` как 2 символа своей ANSI-кодировки и затем урезал до ASCII — отсюда
**два** знака вопроса на одну букву. Показательно, что эталонный
`reference_import.csv`, который «импортировался нормально», вообще не содержит
не-ASCII байтов: там уже было `Mediest?tica M?xico`.

### Добавлено

* **Выбор кодировки результата** в интерфейсе: `UTF-8 с BOM` (новый умолчание),
  `UTF-8 без BOM`, `Windows-1252`, `Windows-1251`. У каждой — подсказка, когда её брать.
* **Галочка «Транслитерировать диакритику»** — `México → Mexico`,
  `Estética → Estetica`, `ā → a`, `® → (R)`. Результат чистый ASCII, испортить
  перекодировкой невозможно. Кириллица не затрагивается (NFKD превратил бы
  `й` в `и` — это порча, а не транслитерация).
* **Отчёт о потерях**: сколько символов не поместилось в выбранную кодировку и
  сколько строк затронуто — показывается в результатах.

### Изменено

* **Кодировка по умолчанию: `utf-8` → `utf-8-sig`** (UTF-8 с BOM). BOM —
  единственный внутриполосный сигнал кодировки, который понимают Excel и
  большинство импортёров. Прежнее поведение доступно как «UTF-8 без BOM».
* Отчёты (`duplicates_report.csv`, `field_fixes_report.csv`) всегда пишутся в
  UTF-8 с BOM — их открывают в Excel, а не импортируют.
* `write_csv()` больше **не падает** на непредставимом символе: деградирует по
  ступеням «символ → без диакритики → `?`» и возвращает статистику. Раньше
  `Alphā Médica` в Windows-1252 дал бы `UnicodeEncodeError` и 500.
* `Content-Type` при скачивании содержит реальную `charset`.

## v2.0 — работа с дублями и перепутанными полями

Основание — разбор реальной таблицы (`leads.xlsx`), см.
[DATA-ANALYSIS.md](DATA-ANALYSIS.md).

### Добавлено

* **Два выходных файла вместо одного**: `crm_import_merged.csv` (дубли
  объединены) и `crm_import_with_duplicates.csv` (строка-в-строку как в
  источнике). Раньше дубли не обрабатывались вообще — 436 строк на входе
  давали 436 на выходе.
* **Объединение дублей** (`dedupe_records`) — union-find по названию компании
  (с учётом хендла в скобках), e-mail, телефону (последние 9 цифр) и сайту.
  Каждый признак включается отдельно. На реальном файле: 436 → 355 строк,
  57 групп; строк совсем без контактов стало 35 → 14.
* **Отчёт `duplicates_report.csv`** — какие строки исходника в какую группу
  попали и по какому признаку.
* **Определение типа значения по содержимому** (`classify_value`,
  `extract_atoms`): `@` → e-mail, только цифры → телефон, домен с реальной
  зоной → сайт.
* **Перенос значений, попавших не в свою колонку** — e-mail из телефонной
  графы уходит в E-mail, ссылка — в Website, номер из графы сайта — в Phone.
  Дубликаты при переносе отбрасываются.
* **Отчёт `field_fixes_report.csv`** — что, откуда, куда и почему перенесено.
* **Автоматическое предзаполнение сопоставления** (`suggest_mapping`) по
  заголовку и содержимому колонки; в UI подсвечено синей рамкой.
* **Ярлыки типа колонки** в UI с раскладкой по типам во всплывающей подсказке.
* **Предупреждения перед конвертацией**: ссылки/почта в телефонной колонке,
  номера без кода страны, переполнение лимита телефонов, «смешанные» колонки.
* **Код страны по умолчанию** — номера без `+` и короче 11 цифр получают
  указанный код (`6611110009` → `+52 6611110009`). Раньше 108 номеров получали
  бессмысленный `+6611110009`.
* Опции: не переносить значения между полями, пропускать строки без названия
  компании, защита от инъекции формул Excel.
* `GET /healthz`, `GET /download/<sid>/<kind>`.
* **31 автотест**, `py tests\test_converter.py` (запускается без pytest).
* Документация: SUPPORT.md, DEVELOPER.md, DATA-ANALYSIS.md.

### Исправлено

* **Ложные срабатывания определения телефонной колонки.** Ключевые слова
  сравнивались по подстроке, поэтому `Contact email`, `Warehouse`, `Hotel name`
  считались телефонными колонками. Короткие слова (`wa`, `tel`, `cel`) теперь
  сравниваются по целому слову, `contact` убрано, добавлен стоп-список
  (`mail`, `website`, `id`, `zip`, `date`, `price`, …), порог по содержимому
  поднят с 0.3 до 0.5 и считается по вердикту всей ячейки.
* **Потеря данных при ошибке этого определения.** Колонка, разбитая на
  «Phone 1/2/3», делала исходный текст ячейки недоступным. Теперь e-mail и
  ссылки из телефонной ячейки сохраняются отдельно и доступны для переноса.
* **Цифры из e-mail превращались в телефон** (`info2024@x.com` → `2024`) —
  адреса вырезаются до поиска номеров.
* **`wa.me/...` попадал и в телефон, и в сайт** — ссылки-телефоны исключены из
  распознавания сайтов.
* **Лимит телефонов в ячейке 3 → 5**; превышение считается и показывается
  предупреждением, а не отбрасывается молча. Автосопоставление «переливает»
  лишние под-столбцы в Other Phone Number вместо того, чтобы бросать их
  несопоставленными.
* **Один номер дублировался в Mobile и Home** — повторы между полями одного
  типа вычищаются.
* **Сессии и папка `uploads/` росли бесконечно** — TTL 6 ч, лимит 50 сессий,
  подчистка осиротевших папок.
* **`/download/<id>`** — строгая проверка `^[0-9a-f]{32}$` вместо вырезания
  слэшей.
* **Ошибка 413** (файл > 25 МБ) возвращала HTML — фронтенд падал на
  `resp.json()`. Теперь JSON.
* Лимиты `MAX_ROWS` / `MAX_COLS`, `TableTooLargeError` больше не мёртвый код.
* Битые папки сессий удаляются, если файл не удалось прочитать.

### Совместимость

* `GET /download/<session_id>` без суффикса продолжает отдавать файл с дублями.
* `/api/convert` по-прежнему возвращает `row_count`, `preview`, `filled`,
  `download_url` на верхнем уровне.
* `converter.build_output_rows()` сохранён как обёртка над `build_records()`.

## v1.0 — первая версия

Веб-интерфейс: загрузка Excel/CSV, разбор телефонов, ручное сопоставление
колонок с полями CRM, выгрузка одного CSV в диалекте `reference_import.csv`
(`;`, CRLF, UTF-8 без BOM) — вместо legacy-скрипта `convert_to_csv.py`,
который писал `,` + BOM + кавычки вокруг каждого поля, из-за чего импорт
«разъезжался».
